# BI-пайплайн

## Выбранная таблица

Для аналитики выбрана таблица delivery_attempts — она хранит каждую попытку доставки вебхука. На одно входящее событие приходится несколько попыток, поэтому таблица растёт быстрее остальных. Метрики: здесь есть статусы (success, failed, timeout), коды ответов от серверов получателей и время ожидания в миллисекундах.

## Метрики

Из этой таблицы построили три среза: сколько попыток было по каждому статусу, как менялось количество попыток по часам и как менялось среднее время ответа. Первое показывает общую картину надёжности доставки, второе помогает найти всплески нагрузки, третье — деградацию скорости серверов получателей.

## Как устроен пайплайн

Debezium читает WAL-журнал PostgreSQL и публикует каждое изменение в Kafka как отдельное сообщение. ClickHouse подписан на этот топик и через материализованное представление автоматически пишет данные в аналитическую таблицу. Metabase подключён к ClickHouse и отображает данные в виде графиков.

При первом запуске Debezium делает начальный снимок — забирает все существующие строки из delivery_attempts и публикует их в Kafka. После этого переходит в режим потока и передаёт только новые изменения по мере их появления.
